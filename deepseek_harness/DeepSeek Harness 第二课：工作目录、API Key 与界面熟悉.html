二、什么是工作目录？

在 DeepSeek Harness 中，Workspace（工作区）就是 AI Agent 可以工作的项目目录。

例如电脑上有一个 Python 项目：

D:\python_project
│
├── main.py
├── utils.py
├── requirements.txt
└── README.md

将：

D:\python_project

设置为 Workspace 后，Harness 就可以围绕这个目录进行工作。

例如：

分析这个项目

Agent 可以读取项目中的文件。

又例如：

帮我找到项目中的 Bug

Agent 可以检查项目代码。

还可以：

创建一个 README.md

或者：

修改 main.py

三、为什么需要 Workspace？

传统聊天机器人主要处理：

用户
 ↓
文字
 ↓
AI
 ↓
文字

而 Harness 面向的是 Agent 工作流：

用户
 ↓
Agent
 ↓
Workspace
 ├── 文件
 ├── 代码
 ├── 项目
 └── 目录

因此 Harness 不只是回答问题，还需要知道：

“我应该在哪个项目里工作？”

Workspace 就是对这个问题的回答。

四、启动目录和 Workspace 的关系

这里需要区分两个概念：

1. 启动目录

执行：

dsh web

时，CMD 当前所在的目录就是 dsh 进程的启动目录。

例如：

cd D:\python_project

然后：

dsh web

那么：

D:\python_project

就是 Harness 的默认文件系统位置。

官方文档明确说明：

dsh 进程会把启动时所在的目录作为默认文件系统位置。

2. Workspace

但是：

启动目录 ≠ 已经选择的 Workspace

一个全新的 Web UI 启动以后，并不会自动选择 Workspace。

需要在界面中：

Choose workspace

然后添加并选择项目目录。

官方文档明确说明，新启动的 Web UI 默认没有选中的 Workspace，必须添加并选择一个工作区。

五、推荐的工作目录启动方式

假设有一个项目：

D:\AI_Project

推荐：

cd D:\AI_Project

然后：

dsh web

启动以后：

Choose workspace
        ↓
选择 D:\AI_Project
        ↓
进入项目 Workspace

这样：

D:\AI_Project

就成为当前 Agent 的工作区。

六、如何选择 Workspace？

进入 Harness Web UI 后，找到：

Choose workspace

点击以后选择项目目录。

例如：

D:\
 ├── AI_Project
 ├── Python_Project
 ├── Spider_Project
 └── Test_Project

如果当前学习的是：

Python_Project

就选择：

D:\Python_Project

七、Workspace 的作用范围

Workspace 是 Agent 工作的主要文件范围。

例如：

D:\Python_Project
│
├── main.py
├── user.py
├── database.py
└── README.md

设置：

D:\Python_Project

作为 Workspace 后，可以让 Agent：

读取文件
   ↓
分析代码
   ↓
修改文件
   ↓
创建文件
   ↓
运行命令

八、Workspace 并不等于“上传文件”

这一点非常重要。

使用 Harness 时：

Workspace

指的是：

电脑上的真实目录。

不是：

上传到云端的文件

例如：

D:\Python_Project\main.py

仍然保存在自己的电脑上。

Harness 根据权限访问这个工作目录中的文件。

九、Workspace 与普通聊天的区别

普通聊天：

你：
帮我看看这段代码有没有问题？

AI：
分析你发送过来的代码

Harness：

你：
帮我检查这个项目有没有 Bug

        ↓

Agent

        ↓

Workspace

        ↓

读取项目文件

        ↓

分析代码

        ↓

执行工具

        ↓

修改 / 测试

        ↓

返回结果

因此：

Workspace 是 Harness 从“聊天工具”进入“项目工作环境”的关键一步。

十、获取 DeepSeek API Key

DeepSeek Harness 需要模型服务才能运行 Agent。

使用 DeepSeek 官方模型时，需要：

DeepSeek API Key

DeepSeek 官方 API 文档明确要求，在调用 DeepSeek API 前需要先创建 API Key。

十一、API Key 是什么？

可以把 API Key 理解成：

程序访问 DeepSeek API 的身份凭证。

普通网页使用：

登录账号
   ↓
密码
   ↓
访问服务

程序调用 API：

程序
 ↓
API Key
 ↓
DeepSeek API
 ↓
模型

因此 API Key 相当于：

“允许这个程序使用我的 DeepSeek API 服务”

十二、获取 API Key

进入 DeepSeek 开放平台：

https://platform.deepseek.com/

登录 DeepSeek 账号。

进入 API Key / API Keys 管理页面。

选择：

创建 API Key

按照页面提示创建。

创建成功后会得到一串密钥。

API Key 通常以：

sk-

开头。

例如：

sk-xxxxxxxxxxxxxxxxxxxxxxxx

示例中的 Key 只是格式示例，不是真实密钥。

DeepSeek 官方文档也说明 API Key 是创建 API 后进行认证所需的凭证。

十三、API Key 安全注意事项

API Key 属于敏感凭证。

不要：

❌ 发到微信群
❌ 发到 QQ 群
❌ 发到 GitHub
❌ 写进公开代码
❌ 截图公开发布
❌ 发给其他人使用

尤其不要把真实 API Key 写进：

main.py
README.md
Git 仓库

如果 API Key 泄露，其他人可能使用你的 API 额度。

十六、配置完成以后需要重启吗？

不需要。

DeepSeek Harness 官方文档明确说明：

模型配置修改后，在下一次请求时立即生效，不需要重启服务器。

因此：

十七、Harness 如何保存 API Key？

DeepSeek Harness 当前不会把 API Key 直接保存到普通的设置配置中。

官方文档说明：

API Key
   ↓
凭据系统
   ↓
$DSH_HOME/.credentials.yaml

Settings 中保存的是：

Credential Reference

而不是明文 API Key。

同时，保存以后页面只会收到脱敏后的凭据描述，不会重新返回完整的明文 Key。

因此：

API Key 配置完成后，如果界面没有再次显示完整 Key，这是正常现象。

三十三、常见问题

1. 没有 Workspace，为什么不能输入任务？

因为新的 Web UI 默认没有选中的 Workspace。

点击：

Choose workspace

添加并选择一个目录。

官方文档明确说明，在选择 Workspace 之前，会话输入区域不可用。

2. API Key 配置以后为什么看不到完整 Key？

这是正常现象。

Harness 的凭据机制采用：

只写
+
脱敏引用

保存后不会再次返回完整明文 Key。

3. API Key 配置以后需要重启吗？

不需要。

保存后下一次请求即可生效。

4. 出现 401 Authentication Fails

通常表示：

API Key 错误

DeepSeek 官方 API 文档中：

401
Authentication Fails

对应的主要原因就是认证失败，需要检查 API Key。

5. 出现 402

如果出现：

402

通常表示：

Insufficient Balance

也就是 API 账户余额不足。

DeepSeek 官方错误码文档将 402 定义为余额不足。
